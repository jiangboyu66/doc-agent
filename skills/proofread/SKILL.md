# 全文校对工作流

## 阶段 1：了解范围
1. 调用 doc_outline，确定需要校对的章节（参数：$ARGUMENTS）。
2. 用 todo_write 建立清单：审阅、汇总、修改、核验。

## 阶段 2：并行审阅（只读）
按章节切分，每个 reviewer 负责 1–3 个章节，**在同一轮中同时发起多个 agent 调用**，让它们并行执行。
给每个 reviewer 的 prompt 必须包含：
- 负责的章节标题与起始段落引用（从大纲复制）；
- 检查重点：错别字、语法、标点（中英文标点混用、全半角）、用词不当、前后术语不一致、数字与单位格式、明显的逻辑问题；
- 输出格式：`[段落引用] 类型：原文片段 → 建议修改（理由）`。

## 阶段 3：汇总
1. 合并所有子代理的结果，去掉重复与不成立的问题（有疑问时自己用 doc_read 核实）。
2. 按"必须修改 / 建议修改 / 待作者确认"分组，向用户展示清单（每条带段落引用），询问：全部修改、只改必须项，还是以批注形式标注。
3. 在用户答复前不要修改文档。

## 阶段 4：修改
- 用户同意修改的条目：逐条 doc_replace_text（带 ref，old_text 取最短的唯一片段），不要合并不相关的修改。
- 待作者确认的条目：用 doc_add_comment 批注。
- 建议开启修订模式，让用户能逐条接受/拒绝（如用户未设置，可询问是否开启：/track on）。

## 阶段 5：核验
启动一个 verifier 子代理，把已修改的段落引用和每处修改要求交给它独立核验；根据结论补漏。
最后向用户汇报：修改了多少处、批注了多少处、有无遗留。
